# MDV Markdown Viewer Pro

Desktop-приложение для просмотра Markdown-файлов, собранное на Electron.

## Требования

- **Node.js** 18+ (протестировано на 24.x)
- **npm** (идёт вместе с Node.js)
- Интернет нужен **только один раз** — при первом запуске на новой машине

## Быстрый старт на новой машине

```powershell
git clone <url вашего репозитория>
cd MDV
npm run setup
```

`npm run setup` выполнит три действия:

1. Установит зависимости (`npm install`)
2. Скачает бинарник Electron нужной архитектуры в `.cache/electron`
3. Сделает одну прогревочную сборку portable-файла — это наполнит `.cache/builder`
   инструментами упаковки (nsis, 7-Zip для вашего процессора и ресурсы)

После этого **все последующие сборки будут работать полностью офлайн**.

## Ежедневные команды

| Команда | Что делает |
|---|---|
| `npm start` | Запуск приложения для разработки |
| `npm run dist` | Сборка portable `.exe` для **x64** |
| `npm run dist:arm` | Сборка portable `.exe` для **ARM64** |

Готовый исполняемый файл появляется в папке `dist/`.

## Архитектуры и «почему сборка падает»

В проекте используется `electronDist: "node_modules/electron/dist"` — это значит,
что portable-файл упаковывается **из того Electron, который установлен на текущей
машине**. Поэтому:

- На **x64-машине** запускайте `npm run dist` — получите x64-исполняемый файл.
- На **ARM-машине** (например, Surface Pro X, Snapdragon) запускайте
  `npm run dist:arm` — получите ARM64-исполняемый файл.

Скрипт `npm run setup` определяет архитектуру автоматически через
`process.arch` и наполняет кэш именно тем набором инструментов, который
нужен текущей машине. Если вы впервые пришли на x64-машину — просто
запустите `npm run setup` один раз, он сам скачает `7zip-win-x64.tar.gz` и
всё необходимое.

## Структура репозитория

```
MDV/
├── index.js          # главный процесс Electron
├── preload.js        # мост между main и renderer
├── web/              # интерфейс приложения (HTML/CSS/JS)
├── package.json      # конфиг приложения и electron-builder
├── package-lock.json # зафиксированные версии зависимостей
├── .npmrc            # прозрачность postinstall-скриптов Electron
├── .gitignore        # игнор: node_modules/, dist/, .cache/
├── setup.js          # провизинер для новой машины
├── .cache/           # ЛОКАЛЬНЫЙ кэш, НЕ в git!
│   ├── electron/     # zip-архивы Electron
│   └── builder/      # nsis, 7-Zip, winCodeSign
├── node_modules/     # зависимости, НЕ в git!
└── dist/             # собранные portable .exe, НЕ в git!
```

## Как устроен офлайн-режим

Обычно `electron` и `electron-builder` при каждой сборке идут в интернет
скачивать бинарники и инструменты упаковки. Мы перенаправляем их кэш в
локальную папку `.cache/` через переменные окружения:

- `ELECTRON_CACHE` — куда Electron складывает свои zip-архивы
- `ELECTRON_BUILDER_CACHE` — куда electron-builder складывает nsis, 7-Zip и т.д.

`npm run setup` делает ровно одну онлайн-сборку, всё нужное оседает в `.cache/`,
и дальше сеть не требуется. Папка `.cache/` **не коммитится** в git — она
воспроизводимо восстанавливается командой `npm run setup` на любой машине.

## Troubleshooting

**`ECONNRESET` при сборке**
Сеть моргнула. Просто повторите `npm run setup` — он делает до 3 попыток
автоматически. Если проблема повторяется — проверьте прокси/антивирус.

**«Битый» архив в кэше**
Если архив скачался не полностью, сборка будет падать. Удалите папку
`.cache\builder\downloads\` и повторите `npm run setup`.

**«portable не запускается на другой машине»**
Скорее всего, вы собрали ARM64-файл на ARM-машине и пытаетесь запустить его
на x64. Используйте правильную команду для архитектуры целевой машины.
